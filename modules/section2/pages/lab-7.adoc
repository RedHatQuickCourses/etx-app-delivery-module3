= Lab 7: Create the GitOps Repository
:navtitle: Lab 7: GitOps Repository
:experimental:

In this lab, you'll create a GitOps repository in GitLab to store the Kubernetes manifests that define your application deployment. This repository will serve as the source of truth that Argo CD continuously monitors and synchronizes with your OpenShift cluster.

By the end of this lab, you will have:

* Created a GitOps repository in GitLab
* Organized Kubernetes manifests for the development environment
* Committed and pushed the initial application manifests

== Create the GitOps Repository

In this exercise, you'll create a new GitLab repository that will store the Kubernetes manifests used by Argo CD for GitOps-based application deployment.

. Retrieve the GitLab URL:
+
[source,bash,role=execute]
----
# Get GitLab URL
GITLAB_URL="https://$(oc get route -n gitlab \
  -l app=webservice \
  -o jsonpath='{.items[0].spec.host}')"

echo "GitLab URL: ${GITLAB_URL}"
----

. Open the displayed GitLab URL in your browser.

. Click btn:[Project] -> btn:[New Project].
+
.Create new project(_Click the image to view it in full size in a new browser tab_)
image::new.png[link={imagesdir}/new.png, width=700]
+
. Select btn:[Create blank project]
+ 
.Create blank project(_Click the image to view it in full size in a new browser tab_)
image::create.png[link={imagesdir}/create.png, width=700]
+
. Create a new project named `etx-app-gitops` in the `software-factory` group.
+
.Project details(_Click the image to view it in full size in a new browser tab_)

[source,bash,role=execute]

git clone ${GITLAB_URL}/software-factory/etx-app-gitops.git

== Create the Development Environment Manifests

Create the Kubernetes manifests that define the application's development environment.

. Confirm you are inside the **etx-app-gitops** directory that you cloned in previous step.

. Once you are inside the cloned repository, create **environments/dev/deployment.yaml** as shown below:
+
[source,bash,role=execute]
----
mkdir -p environments/dev
cat > environments/dev/deployment.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: etx-app-base-app
  namespace: etx-app-dev
  labels:
    app: etx-app-base-app
  annotations:
    instrumentation.opentelemetry.io/inject-java: "true" # (1)
spec:
  replicas: 1
  selector:
    matchLabels:
      app: etx-app-base-app
  template:
    metadata:
      labels:
        app: etx-app-base-app
      annotations:
        instrumentation.opentelemetry.io/inject-java: "true" # (1)
    spec:
      containers:
        - name: etx-app-base-app
          image: image-registry.openshift-image-registry.svc:5000/etx-app-dev/etx-app-base-app:main # (2)
          ports:
            - containerPort: 8080
          resources:
            requests:
              cpu: 250m
              memory: 512Mi
            limits:
              cpu: "1"
              memory: 1Gi
          env:
            - name: POSTGRESQL_HOST
              value: "parasol-db.etx-app-dev.svc.cluster.local"
            - name: POSTGRESQL_DATABASE
              value: "parasol"
            - name: POSTGRESQL_USER
              value: "parasol"
            - name: POSTGRESQL_PASSWORD
              value: "parasol"
            - name: KAFKA_BOOTSTRAP_SERVERS
              value: "parasol-kafka-kafka-bootstrap.etx-app-dev.svc.cluster.local:9092"
EOF
----

NOTE: The OpenTelemetry annotation automatically injects the Java agent using the Instrumentation custom resource created during the supporting services setup.

NOTE: The container image tag is updated automatically by the CI pipeline after a successful build.

. Create the Service manifest named **environments/dev/service.yaml**:
+
[source,bash,role=execute]
----
cat > environments/dev/service.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: etx-app-base-app
  namespace: etx-app-dev
spec:
  selector:
    app: etx-app-base-app
  ports:
    - port: 8080
      targetPort: 8080
EOF
----

. Create the Route manifest named **environments/dev/route.yaml**:
+
[source,bash,role=execute]
----
cat > environments/dev/route.yaml <<'EOF'
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: etx-app-base-app
  namespace: etx-app-dev
spec:
  to:
    kind: Service
    name: etx-app-base-app
  port:
    targetPort: 8080
  tls:
    termination: edge
EOF
----

== Commit the Initial Manifests

Commit the development environment manifests and push them to the GitOps repository.

. Configure your Git identity:
+
[source,bash,role=execute]
----
git config --global user.email "platform-developer@example.com"
git config --global user.name "Platform Developer"
----

. Retrieve the GitLab administrator credentials:
+
[source,bash,role=execute]
----
GITLAB_ROOT_PASSWORD=$(oc get secret \
  -n gitlab \
  gitlab-gitlab-initial-root-password \
  -o jsonpath='{.data.password}' | base64 -d)

echo "Root Username: root"
echo "Root Password: ${GITLAB_ROOT_PASSWORD}"
----

. Commit and push the manifests. When prompted for Git credentials, use the **GitLab root** username (`root`) and the password retrieved in the previous step:
+
[source,bash,role=execute]
----
git add -A
git commit -m "feat: add dev environment manifests"
git push origin main
----

Once the changes are pushed, the GitOps repository contains the Kubernetes manifests that Argo CD will use as the desired state for the development environment in the following labs.
