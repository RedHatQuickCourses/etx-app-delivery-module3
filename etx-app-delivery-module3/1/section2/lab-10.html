Lab 10: Integrate CI with GitOps

In this lab, you’ll connect your Tekton CI pipeline to your GitOps repository so that every successful build automatically updates the application image referenced by Argo CD.

By the end of this lab, you will have:

  • Created a Tekton Task that updates the GitOps repository with a new image tag

  • Extended the CI pipeline to invoke the GitOps update task after a successful image build

  • Automated the flow from code commit to GitOps repository update

Create the GitOps Update Task

In this exercise, you’ll create a Tekton Task that clones the GitOps repository, updates the application image tag, commits the change, and pushes it back to GitLab.

  1. Open a terminal in your OpenShift Dev Spaces workspace or launch the Web Terminal from the OpenShift console.

  2. Create the Task:

    oc apply -f - <<'EOF'
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: update-gitops-repo
  namespace: etx-app-dev
spec:
  params:
    - name: gitops-repo-url
      type: string
    - name: image-tag
      type: string
    - name: environment
      type: string
      default: dev
  workspaces:
    - name: source
  steps:
    - name: update-image
      image: registry.access.redhat.com/ubi9/ubi:latest
      script: |
        #!/bin/bash
        set -e

        # Install git
        dnf install -y git && dnf clean all

        REPO_URL="$(params.gitops-repo-url)"
        GITLAB_HOST=$(echo "$REPO_URL" | sed -E 's|https?://([^/]+)/.*|\1|')

        git config --global url."https://etx-platform-bot:openshift@${GITLAB_HOST}/".insteadOf "https://${GITLAB_HOST}/"

        git clone "$REPO_URL" /tmp/gitops
        cd /tmp/gitops/environments/$(params.environment)

        # Update the image tag in the deployment manifest
        sed -i "s|image:.*etx-app-base-app:.*|image: image-registry.openshift-image-registry.svc:5000/etx-app-dev/etx-app-base-app:$(params.image-tag)|" deployment.yaml

        git config user.email "pipeline@openshift.local"
        git config user.name "Tekton Pipeline"
        git add .
        git commit -m "Update etx-app-base-app image to $(params.image-tag)"
        git push
EOF

    The Task updates the deployment manifest in the GitOps repository with the newly built image tag and pushes the change back to GitLab.

Update the CI Pipeline

Next, extend the existing CI pipeline so it automatically executes the GitOps update task after the container image has been built successfully.

  1. Retrieve the GitLab URL:

    GITLAB_URL="https://$(oc get route \
  -n gitlab \
  -l app=webservice \
  -o jsonpath='{.items[0].spec.host}')"

echo "${GITLAB_URL}"

  2. Edit the existing pipeline:

    oc edit pipeline etx-app-base-app-ci -n etx-app-dev

  3. Under the spec.tasks section, add the following task definition:

        - name: update-gitops
      runAfter: [build-image]
      taskRef:
        name: update-gitops-repo
      params:
        - name: gitops-repo-url
          value: SUBSTITUTE-GITLAB-URL-HERE/software-factory/etx-app-gitops.git
        - name: image-tag
          value: $(params.git-revision)
        - name: environment
          value: dev
      workspaces:
        - name: source
          workspace: shared-workspace
Replace SUBSTITUTE-GITLAB-URL-HERE with the GitLab URL retrieved earlier. If you’re recreating the pipeline using a shell heredoc, you can use the ${GITLAB_URL} variable instead.

Verify the Integration

You’ll trigger the CI pipeline by making a code change and verify that the GitOps repository is updated automatically. You’ll then confirm that Argo CD detects the change and deploys the new application version.

  1. Open a terminal in your Dev Spaces workspace.

  2. Make a small change to the application and commit it:

    echo "====" >> README.md
git add -A
git commit -m "Verify CI to GitOps integration"
git push -u origin feature/add-devfile

  3. Monitor the pipeline until it completes successfully:

    oc get pipelineruns -n etx-app-dev --watch

    Wait until the latest PipelineRun shows a status of Succeeded.

  4. In Openshift console terminal, verify that the GitOps repository etx-app-gitops has been updated automatically:

    GITLAB_URL="https://$(oc get route -n gitlab \
  -l app=webservice \
  -o jsonpath='{.items[0].spec.host}')"
git clone ${GITLAB_URL}/software-factory/etx-app-gitops.git
git pull
grep "image:" environments/dev/deployment.yaml

    Sample output:

    image: image-registry.openshift-image-registry.svc:5000/etx-app-dev/etx-app-base-app:30615ccd54c01ac19f28a0a71df611ff22dde254

    The image tag should now match the Git commit SHA from the pipeline execution.

  5. View the latest Git commit:

    git log -1 --oneline

    You should see a commit similar to:

    1df86ef (HEAD -> main, origin/main, origin/HEAD) Update etx-app-base-app image to 30615ccd54c01ac19f28a0a71df611ff22dde254

  6. Verify that Argo CD synchronized the change:

    oc get applications -n openshift-gitops

    Confirm that the etx-app-dev application reports Synced and Healthy.

  7. Verify that the application is running the updated image:

    oc describe deployment etx-app-base-app -n etx-app-dev | grep Image:

    Sample Output:

    Image:      image-registry.openshift-image-registry.svc:5000/etx-app-dev/etx-app-base-app:30615ccd54c01ac19f28a0a71df611ff22dde254

    The deployment should reference the same image tag that was committed to the GitOps repository.

The complete deployment flow is now fully automated:

  • A code commit triggers the Tekton CI pipeline.

  • Tekton builds and pushes a new container image.

  • The pipeline updates the GitOps repository with the new image tag.

  • A new commit is pushed to GitLab automatically.

  • Argo CD detects the Git change and synchronizes the application.

  • OpenShift deploys the updated application without any manual intervention.
