Lab 12: Configure Quay for Image Promotion

In this exercise, you’ll prepare Quay for the image promotion workflow by creating the repository used by the promotion pipeline and storing robot account credentials securely in Vault.

By the end of this exercise, you will have:

  • Created the etx-app organization and etx-app-base-app repository in Quay

  • Created a robot account for non-interactive image promotion

  • Stored the Quay robot credentials in Vault for use by the promotion pipeline

The promotion pipeline pushes images to Quay at etx-app/etx-app-base-app and retrieves authentication credentials from Vault at secret/registry/quay.

Interactive users authenticate to Quay using Keycloak Single Sign-On, while CI/CD pipelines use robot accounts for automated, non-interactive authentication.

Create the Quay Organization and Repository

Create the Quay organization and repository that will store promoted application images.

  1. Open the Quay URL from your RHDP lab environment.

    Figure 1. Quay Login Page(Click the image to view it in full size in a new browser tab)

  2. Sign in using ETX Keycloak Single Sign-On with one of the lab accounts:

    • platform-admin / openshift

    • platform-developer / openshift

  3. If prompted, remove any hyphens (-) from the suggested username and click Confirm Username.

    Figure 2. Validate Quay Username

  4. Click Create New Organization.

    Figure 3. Create Organization

  5. Create an organization named etx-app.

    Figure 4. Create the Organization

  6. Inside the organization, click Create New Repository

  7. Configure the repository and click Create Public Repository.:

    • Repository Name: etx-app-base-app

    • Visibility: Public

      Figure 5. Create Repository
The organization and repository names must match the destination referenced later by the promotion pipeline: etx-app/etx-app-base-app.
Although the repository is public, anonymous image pulls are disabled in this Quay deployment. Runtime clusters must authenticate using an image pull secret.

Create a Robot Account

The promotion pipeline requires a robot account to authenticate to Quay without using interactive Keycloak credentials.

  1. From the etx-app organization, click the Settings icon.

    Figure 6. Organization Settings

  2. Under User and Robot Permissions, open the dropdown and click Create Robot Account.

    Figure 7. Create Robot Account

  3. Create a robot account named promoter and click Create robot account.

    Figure 8. Robot Account Name

  4. Grant the robot account Write permission to the repository.

    Figure 9. Assign Write Permission

  5. Open the newly created robot account by clicking etx-app+promoter

    Figure 10. Robot Account

  6. Copy the generated credentials:

    • Username: etx-app+promoter

    • Token: Generated robot token

      Figure 11. Robot Account Credentials
Save the robot token before leaving the page. It will be required when creating the Vault secret.

Store Quay Credentials in Vault

Store the Quay robot account credentials in Vault so the promotion pipeline can retrieve them securely at runtime.

  1. Retrieve the Quay hostname:

    oc get route -n quay \
  -l quay-component=quay-app-route \
  -o jsonpath='{.items[0].spec.host}' && echo

  2. Retrieve the Vault root token:

    oc get secret etx-vault-bootstrap \
  -n vault \
  -o jsonpath='{.data.root-token}' | base64 -d && echo

  3. Open the Vault URL from your lab environment.

  4. Sign in using the Token authentication method and paste the token retrieved above.

    Figure 12. Sign in to Vault

  5. From the Vault dashboard, open the secret/ secrets engine.

    Figure 13. Secret Engine

  6. Click Create secret.

    Figure 14. Create Secret

  7. Create a secret with the path:

    registry/quay

  8. Add the following key-value pairs:

    • server: Quay hostname returned by the earlier command in Step 1 (without https://)

    • username: etx-app+promoter

    • password: Robot token copied from Quay

      Figure 15. Create Vault Secret

  9. Click Save.

    Figure 16. Completed Secret
The promotion pipeline authenticates to Vault using Kubernetes authentication and retrieves these credentials automatically during execution. No Quay credentials are stored directly in the pipeline definition.
